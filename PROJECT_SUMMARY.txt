================================================================================
                            项目概述
================================================================================

本项目是一个完整的优先级线程池实现，展示了如何在多线程系统中根据任务优先
级来高效地调度执行任务。

核心特性:
  ✓ 10 个优先级等级 (1=最低, 10=最高)
  ✓ 按优先级存储任务，高优先级优先执行
  ✓ 同一优先级任务按 FIFO 顺序执行
  ✓ 线程安全的并发管理 (mutex + cond)
  ✓ 类似哈希表"拉链法"的数据结构设计

【问题 1】10 个任务的执行顺序是怎样的？
─────────────────────────────────────────────────────────────────────────────

任务分布:
  优先级 1: Task1, Task3, Task10      (3 个)
  优先级 2: Task4                     (1 个)
  优先级 3: Task6                     (1 个)
  优先级 4: Task8                     (1 个)
  优先级 5: Task7                     (1 个)
  优先级 6: Task9                     (1 个)
  优先级 7: Task2, Task5              (2 个) ← 最高

执行顺序（按优先级从高到低）:
  优先级 7: Task2 → Task5  ✓ 第一时间执行
  优先级 6: Task9
  优先级 5: Task7
  优先级 4: Task8
  优先级 3: Task6
  优先级 2: Task4
  优先级 1: Task1 → Task3 → Task10  ⏳ 最后执行

关键观察:
  • Task1 虽然是第一个被推送，但优先级最低，所以被延迟
  • Task2 虽然是第二个被推送，但优先级最高，所以首先执行
  • 这就是优先级线程池的威力！


【问题 2】为什么说这是"拉链法"？
─────────────────────────────────────────────────────────────────────────────

数据结构设计:
  tasks[10] 是一个链表数组，每个元素是一条链表
  
  tasks[0]  → [Task1] → [Task3]      (优先级 1 的任务)
  tasks[1]  → NULL                   (优先级 2)
  tasks[2]  → NULL                   (优先级 3)
  ...
  tasks[6]  → [Task2] → [Task5]      (优先级 7 的任务)
  ...

为什么叫"拉链法":
  与哈希表的"拉链法"解决冲突完全相同！
  
  哈希表:       task1.hash = 5 ┐
                task2.hash = 5 ├─→ bucket[5]: [task1]→[task2]
                task3.hash = 5 ┘
  
  优先级队列:  task1.pri = 7 ┐
                task2.pri = 7 ├─→ tasks[6]: [Task2]→[Task5]
                ┘

相似之处:
  • 都是用"数组 + 链表"的二维结构
  • 数组维度: 哈希值 / 优先级等级
  • 链表维度: 冲突的元素 / 同优先级的任务
  • 都是 O(1) 入队，O(P) 查找最优元素


【问题 3】架构思路与执行过程
─────────────────────────────────────────────────────────────────────────────

核心设计:
  1️⃣ 多队列分类存储
     按优先级将任务分别存储在 10 个队列中
  
  2️⃣ 优先级驱动调度
     工作线程从高到低优先级查找任务
  
  3️⃣ 互斥锁保护
     mutex 保护队列数组的修改
  
  4️⃣ 条件变量高效等待
     cond_var 避免忙轮询，节省 CPU

执行流程:
  初始化    → 创建 3 个工作线程，全部阻塞在 pthread_cond_wait()
  推送任务  → 将任务按优先级插入对应队列，唤醒等待线程
  并发执行  → 线程从高到低优先级查找任务并执行
  销毁清理  → 标记下班，等待所有线程退出

关键算法 (出队):
  for (i = 9; i >= 0; i--) {        // 从最高优先级开始
      if (tasks[i] != NULL) {
          task = tasks[i];           // 找到任务
          LIST_REMOVE(task, ...);    // 摘下
          break;                     // 立即返回
      }
  }

================================================================================
                        数据结构与复杂度
================================================================================

入队操作 (nPriorityThreadPoolPushTask):
  时间复杂度: O(1)
  空间复杂度: O(1)
  实现: 直接在 tasks[priority-1] 的链表头插入

出队操作 (从高到低查找):
  时间复杂度: O(P) ≈ O(10) ≈ O(1)
  实现: 遍历 10 个优先级队列

锁持有时间:
  入队: O(1)
  出队: O(10)
  任务执行: 0  ← 关键：执行时不持有锁，允许并发操作

对比方案:
  方案        入队    出队    任务执行  总耗时(10个任务,3线程)
  ────────────────────────────────────────────────────────────
  单队列      O(1)   O(1)    O(1)      ~4-5s   (低优先级先执行❌)
  多队列      O(1)   O(10)   O(1)      ~4s     (高优先级先执行✅)
  堆/红黑树   O(logN) O(logN) O(1)      ~4s     (复杂度好但实现复杂)
